## 判斷與除錯

- **捲軸必須共用真正的位置來源**：不能把全螢幕 CLI 的相對滾輪假裝成 0–100 絕對位置；直接跳轉也不能用逐段搜尋冒充。先確認 CLI 能否輸出原生 scrollback，必要版面變化先說明。

- **接續對話要測 CLI 自己的選單入口**：預填 session id 會遮住辨識失敗；需用未綁定終端機選回舊對話，並確認真 CLI 畫面隨拖曳改變。
- **鏡像同步前先查目的地資料與 junction**：robocopy /MIR 必須排除 user-data 並加 /XJ；用真 junction 哨兵檔驗證，不能只驗產物複製成功。

- **先量再改**：直覺要改的開關，量過常常不該改；「卡頓」先問是做得慢還是每次都重做（找重複的 O(輸入大小)）。
- **量不到效果先確認量測環境有沒有讓那件事發生**（`show:false` 視窗不做高亮、被遮住的視窗沒有 rAF），兩種設定給出一樣的錯，變因就不在設定。
- **工具回成功而結果明顯不對，先驗產物、不要重跑**；建置產物出怪事整個刪掉重打。
- **「查不到」先確認是查不到還是自己送錯**：外部查詢失敗先用 `curl` 原樣打一次。
- **使用者說「我這邊是對的」先當真去驗**：寫 probe 打真上游列出矩陣，比讀十遍程式碼快。
- **被擋住先做對照實驗找出真正變因**：Grok 卡 Cloudflare，逐一換 UA 變體（偽裝 Chrome、縮版號、帶 App 名、原樣）幾輪就定位，不要憑「偽裝越像越好」的直覺。
- **「三個結果都一樣壞」不等於變因已控制**；沒滿足前提的觀察不能推翻假設。
- **「改完又變回原樣」多半是修法只在乾淨環境成立**：回歸要先重現使用者手上的髒狀態。
- **「排查工具正常、正式路徑不正常」＝工具改變了現場**：先問工具多做了什麼。
- **刪不掉的檔案先查誰抓著，答案常是自己**；用 Restart Manager／`handle64`，不要只看命令列。
- **PATH 壞掉的症狀不會指向 PATH**（`command not found`、`ENOENT`、找不到 editor）：先數 PATH 有幾項；子 shell 壞掉從「誰 spawn 的」往上追。
- **單位要找對面自己附的文件，不要拿實收金額反推**；倍率整齊（剛好 10.00）就是單位／口徑錯的指紋。
- **「這件事做不到」的結論留在註解裡久了會變成事實**；官方 API 有限制不等於沒有其他方法，使用者給反例就查原始碼與本機行為。
- **同一個寫法失敗兩次就換方法**（字串替換連兩次對不上，就改用會報錯的工具）。
- **控制字元與反斜線不要直接寫進原始碼／heredoc**：用 `String.fromCharCode` 或程式產生。

## 架構與實作

- **原生捲動不代表 CLI 會重播完整舊對話**：用真長對話驗第一筆，不能只看最近回答；需要補歷史時保留同一 xterm／PTY 與即時輸入，先取得使用者對補回內容的選擇。
- **Claude 預設 home 不應明設 CLAUDE_CONFIG_DIR**：明設 ~/.claude 會把全域設定改找 ~/.claude/.claude.json，出現首次啟動畫面；預設 home 清除覆寫，僅真正自訂 home 才帶環境鍵。

- **核心只有幾個資料結構**：移植別人的架構借的是互動模型不是實作量級；連哨兵值一起檢查（`-1` vs `null`）。
- **引進大型前端套件前先確認 build 形式跟本專案載入方式相容**，並看它拖了什麼進來。
- **「這個平台有沒有內建 X」一定要實測**（Electron 43 沒有 PDF 檢視器）。
- **會被 bundler 吃掉的寫法要在真正的載入方式下測一次**：判準是正式環境誰在載這個檔案。
- **有生命週期的資源跟著擁有者一起收**：換整批容器時問「舊的那批誰收」；dispose 了不等於記憶體放掉（還有誰指著它）；`hidden` 的 iframe／video 照樣在跑。
- **要比內容有沒有變，留「上次那份」的參考比**，不要為了比對再取一次內容。
- **影子副本要問多久需要準一次**，並寫清楚真正來源在哪。
- **「記得收」不是修法，讓工具自己收才是**：建立與清理綁在同一入口，再用守門測試擋繞路。
- **清理程式碼用最壞輸入、在最新 runtime 測**（junction ＋ Node 24）。
- **改「取值」函式的 fallback 前，先查有沒有人拿回傳值當守衛**；一個函式被當兩件事用，收緊一件會弄壞另一件。
- **同一份資料要有單一來源**；可見狀態要跟資料上下文一起失效。
- **重畫整份清單會洗掉進行中的互動**（確認鈕、改名框、框選、捲動位置）：就地更新那一列。
- **新寫的初始化函式要確認真的被呼叫**；「載得起來」本身要有測試（`module.exports` 的 ReferenceError）。
- **逐一列舉的白名單新增方法要同步補**；同一個結構性陷阱出現在第二個模組時，在那個模組也補一條地雷。
- **改 require 目標不是等價替換**：沿呼叫鏈找誰負責初始化。
- **同一件事被兩層各做一次，上層會吃掉下層資訊**：補值函式只能有一個呼叫端。
- **上游函式庫預設樣式少寫一個屬性，症狀會出現在無關的地方**：去看那一層，不要在下游疊補丁。
- **同一個 API 有單次上限時呼叫端要切段**；沉默的截斷比拋錯難查十倍。
- **啟動要有重入旗標**；切頁只卸資源不作廢工作，下一輪會把資源載回來。
- **相容舊 App 的庫要拷走再寫**（跟還在跑的程式搶 SQLite 會兩邊都壞）。

## 外部整合

- **mock 測得再綠也證明不了對面長什麼樣**：架構押在哪個假設上，那個假設最先驗（`probe-*.js` 打真流量）。
- **移植時來源的奇怪選擇通常是它踩過的坑**；但照抄前也要問「他們那樣做對嗎」。
- **使用者指定的接法也要先驗**：實測兩分鐘 > 照抄一句需求。
- **官方的自動化只在你沒設時生效**（`-fit on`）；翻譯／相容層不該覆蓋使用者的明確指名。
- **更新方式看它實際怎麼裝的**，不是「有 npm 套件」。
- **「該續期了」≠「已經不能用」**；「清掉快取」≠「換 token」；語意窄的旗標只能由產生該語意的路徑設定。
- **代跑外部 CLI 的 stdio 很要命**（`execFile` 留著不 EOF 的 stdin 會卡死對方）。
- **額度／端點先對真實回應再命名欄位**；上游會對同一故障給兩種說法。
- **反機器人系統看的是「說法一致」不是「像 Chrome」**：Cloudflare 認得出 Electron，偽裝反而被當機器人；Google 登入則相反。每站分開驗。
- **一次實測過關不代表修好**：Grok「保留 Electron UA 就放行」隔天就失效。內嵌瀏覽器過不了的，改借真瀏覽器的通行證（cf_clearance 綁 UA，要連 UA 一起帶）。
- **「能接上」要用真的客戶端整串跑**：AGY 自我測試（單句、無工具）一直綠，真 Claude Code 帶 23 個工具卻第一句就 400；整合驗收至少跑一次「純文字＋一次工具往返」。
- **子代理的量測說「本來就正常」時，症狀還在就是量錯層**：縮圖 API 取得到畫面，使用者看到的是 Explorer 疊上去的覆蓋圖示。
- **測試別一直開視窗**：真瀏覽器實驗一次只開一個、測完馬上關，先想清楚每次要驗什麼。

## 資料、計價與統計

- **先確認涵蓋率再談準確率**；真實資料才問得出正規化夠不夠。
- **「累計」與「單輪」長得一樣，加錯差十倍**；同欄位兩種價錢不能只算便宜的。
- **「填 0」比「留空」更會騙人**：沒有就回 `null` 並在 UI 講少算了什麼；推導只當退路而退路不可回 0。
- **上限值會靜靜吃掉資料**；只給總數等於沒說，數字讓人驚訝先問它由什麼組成。
- **來源未連線不可合成保守額度**；游標認絕對路徑會在檔案搬移時重算（模擬 `renameSync` 就能重現）。
- **解析帶語意的 ID 前先驗版本**（UUIDv7 時間戳）；重播防護不可只靠單一標記。
- **新增「曾經成功」欄位要驗升級前就已失敗的資料**；有既存成功診斷才補回，不憑空恢復登入。

## 測試

- **新回歸測試先在修復前跑一次，紅了才算數**；PASS 也要證明它會 FAIL（運算子優先順序讓斷言恆真）。
- **「子代理都綠了」不等於功能會動**：先看那支測試到底測了什麼（diff 章節、grep 新功能選擇器）。
- **測試測到被繞過的那一層就會一直綠**；同一份程式碼算出的數字不能用它自己的測試證明。
- **驗收走使用者真的會做的那串動作**（捲動、切分頁、開右欄），只驗「開啟時」等於半套：關著／空的／還沒載入也要量。
- **分階段畫出的畫面，等「那件事本身」不是等粗略數量**；UI 斷言等量得到尺寸，不睡固定時間。
- **合成事件測不到事件路徑的 bug**：`dispatchEvent(new MouseEvent('dblclick'))` 直接打在列上永遠綠，真滑鼠第一下重畫後 dblclick 根本到不了容器。互動類回歸用 `Input.dispatchMouseEvent`。
- **CDP 點擊會被吞**：等待條件要包住點擊本身；背景視窗不派送 focus／blur，改驗等價動作。
- **整批 CDP 一起紅先懷疑環境**（PATH 殘缺、worktree junction 的 node_modules）；先拿沒改動的 exe 跑一次當基準。
- **驗收不可替正式產物補檔**：補了只證明測試環境修好，不證明使用者拿到的安裝包。
- **發版前拿新 asar 跟上一版逐檔比對**，不要只看 exit 0。
- **會外溢到 App 之外的動作，測試路徑先切斷**（模擬 Ctrl+V、taskkill、改使用者設定）；E2E 跑在真實資料上，只用 `[data-id]` 定位。
- **測試用假資料自己也要驗**：二進位樣本用程式產，不憑記憶貼。
- **斷言挑功能真的能保證的事**（`WS_EX_TOPMOST` 而不是誰在前景）；不綁會隨設計調整的長度或位置；定位量相對關係。
- **只驗截圖驗不到原生控制項**；原生自繪要另驗局部 WM_PAINT，PrintWindow 全幅重畫會掩蓋問題。
- **修會斷線的 sidecar 要用真正的指令流量驗**，看程序實際活多久，不看有沒有報錯。
- **提權殭屍程序會讓後續每輪都紅**：每輪開始前確認上一輪死透。
- **餵假資料給 renderer 不要鑽 contextBridge 的洞**：另起 `contextIsolation: false` 的殼。
- **改動全域狀態的測試段落要收尾還原**；e2e 別把小模型的用詞正確性當紅燈。

## UI 與樣式

- **使用者指定滑入顯示、離開消失時，不加點擊釘選；滑鼠離開也不能被按鈕焦點阻止收合。**
- **捲軸必須對應可捲動內容；不能把全螢幕 CLI 的相對滾輪偽裝成固定 50% 並在放開時回彈。** 保存紀錄只能建清單；「在終端機跳轉」必須捲動原 CLI，不得用唯讀文字畫面替代。驗收須確認同一終端機與 PID、仍可輸入，不能只斷言文字出現。

- **改完版面去看一眼真的畫面**：窄面板「誰先縮」要當契約寫進測試（量內容有沒有溢出自己那格）。
- **修 A 時順手壓過瀏覽器內建樣式會生出更大的 B**（`[hidden]`、`dialog:not([open])`）。
- **包一層之後原本的 CSS 收斂就失效**；共用容器的內距寫在子元素上，新子元素一定漏。
- **hover 才出現的操作等於沒有；藏在點擊後面等於沒做；列出可改的狀態就要在同一列給改的方法。**
- **圖表沒有 Y 軸等於把解讀丟給使用者**；讀不到值 push 0 會壓扁縮放。
- **拖曳中改 DOM 順序是卡頓來源**：只用 transform，放開才動 DOM。
- **CSS 動畫掛在會被重建的節點上永遠轉不完**（終端機游標、spinner）。
- **輸入法候選字窗跟著系統看到的輸入框走**：自繪游標的元件要自己把隱形 textarea 挪到游標上。
- **使用者說「像檔案總管那樣」就照原生手感做**：就地打字、開新分頁，不用對話框湊。
- **原生自繪 UI**：空字串／無效矩形先略過（`DrawTextW` 省略號會讀無效指標）；面板換底色時容器、列、空白區、捲軸要一致；全域快捷鍵先看焦點屬於誰；滑桿要驗畫出的圓點與命中區一起動。

## Electron／Windows

- **啟動慢多半是頂層 require 整張模組圖**，不是 Electron 本身。
- **不是每個 fs API 都懂 asar，外部程序也讀不到 asar**：從源碼跑永遠綠，一定要驗 final package。
- **打包「沒報錯」不等於成功**：asar 錯位（起得來但整頁 SyntaxError）與中斷（啟動無 log）症狀不同；「檔案被抓著」前先問「為什麼這麼大」。
- **透明視窗是坑**；蓋在別人程式上的視窗先問會不會偷焦點；還原座標要驗螢幕存在。
- **背景常駐時只有計時器被節流，訊息派送不會**；藏起來的 webview 會丟圖塊，卡頓去 GPU 程序找。
- **在 Agent 環境啟動 GUI 不要掛著等或重定向輸出**（Job Object 會整組砍）。
- **GUI 子程序的 `windowsHide: true` 可能藏掉整個視窗**：只用在背景工作。
- **不確定安裝程式參數先從 exe 撈 usage 字串**；「裝好了」跟「找得到」是兩件事。
- **OEM 沒填的欄位會回像資料的字串**（`Default string`），統一一處清掉；效能計數器選錯類別慢十倍。
- **Windows 預設關聯要同時維護新舊 Hash 並回讀實際 handler**；失敗還原逐項做完，不在第一個錯誤就停。

## 音訊／ASR／本地 LLM

- **靜音與非語言片段在訊號層擋掉**，不交給 AI 判斷。
- **括號式 meta-prompt 小模型會複誦**：指令放 system、前文當上一輪；失敗別把原文冒充譯文寫進 history。
- **不要用 regex 剝前綴當修復**；自家「清理」與在地化詞彙表也會污染正確譯文。
- **載入模型 ≠ 可快速推論**；別用 0.8B 當語言偵測器；量化不背模型的鍋。
- **切段策略用實測收斂**；佇列要有上限丟最舊；await 後（含 `finally`）重檢 session 狀態。
- **學習型功能要保守**；一組規則各自都對合起來會錯（字典接力）。
- **「A 沒生效」通常是 A 只活在管線前半段**（字典送進模型後沒再套一次）。
- **「保守」要看單位長度**；提示詞裡的「輸出語言」會被當成翻譯指令。
- **使用者要的功能可能物理上不存在**：做一個切了也沒差的開關比不做更糟。

## 流程與溝通

- **紀錄的分段讀取不等於畫面必須分頁**：完整對話可自動接成同一頁；概況欄位靠左自然排，不用等寬格把中間空隙拉大。
- **錯誤訊息寫給還沒做到那件事的人看**；狀態碼分類看「使用者下一步該做什麼」；錯誤必須浮上 UI。
- **UI 的求助訊息會把人帶去修錯的東西**：先確認它說的是真因。
- **安全規範按性質寫**（「任何上游可控又會顯示的字串」），不然舊模組跟不上。
- **該不該共用看取捨是不是同一個**，不是值長得像不像。
- **回報未處理項目每項都帶「是／不是 bug」與依據**；明確要求的功能不能只留在未來清單。
- **使用者仍在用電腦時不移動滑鼠、不搶焦點、不開系統設定**；要手動開一份走 `npm run dev:sandbox`。
- **背景自動同步的頻率要套到所有入口**（定時、開頁、開彈窗、重啟）；手動刷新另走明確按鈕。
- **更新顯示方式要分入口**：結束 App 靜默、手動有進度、關機登出不裝。

# AI 紀錄置頂標題

- 紀錄標題可能就是整段第一則提問；置頂區使用可展開的短摘要，操作鈕另排一列，避免長文字把控制列撐滿畫面。
